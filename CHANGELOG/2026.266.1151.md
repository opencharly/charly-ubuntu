# 2026.266.1151 — feat: add the check-charly-ubuntu-repo R10 bed for the published package repo

## Summary of changes

Relocate the `check-ubuntu-repo` R10 check bed (and the `ubuntu-repo-vm` template it deploys) from `opencharly/charly`'s `charly.yml` into this repo, which OWNS the artifact the bed tests.

WHY: a check bed must live in the repo that owns what it tests. The check-bed runner's dev-tree override (`proc.SelfSuperprojectOverridePair`, `spec/proc/repo_override.go`) points the bed PROJECT's own superproject's `@github` refs at the local tree. In this umbrella every submodule's superproject is `opencharly/opencharly` (which hosts no candies), so a candy owned by another repo was never exercised as in-development code while its bed sat in `charly`. Relocated here, the bed composes the LOCAL candy with no `@github` pin.

**Changed files (2, +145/-0):**
- `charly.yml` (+129) — adds `ubuntu-repo-vm` (the disposable `cloud_image` Ubuntu 24.04 noble template: `libvirt` + `uefi-insecure` + `distro: ubuntu` + generated SSH key) and the `check-ubuntu-repo` bed that composes it (`from: ubuntu-repo-vm`, `disposable: true`, 7-step `plan:`). No namespace import — the box resolves locally.
- `.gitignore` (+16, NEW) — the standard generated-artifact rules: `.build/` (recreated by `charly box generate`/`build`), `.containerignore` / `.dockerignore` (podman/docker context ignores), `.check/` (eval-run scratch), `output/` (VM/disk-image build outputs), editor scratch (`*.swp`, `*~`), and `charly migrate` rollback backups (`*.bak`, `*.bak.*`).
