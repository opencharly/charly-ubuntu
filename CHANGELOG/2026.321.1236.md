### The step that makes this bed able to fail

```
- check: the booted guest reports Ubuntu 26.04 LTS (resolute), not the retired noble baseline
  id: guest-is-resolute
  command: |
      grep -q 'VERSION_CODENAME=resolute' /etc/os-release \
        && grep -q '26.04' /etc/os-release \
        && echo GUEST-IS-RESOLUTE
```

Without it the bed asserts only the *install path*, which a revert to the retired baseline would satisfy just
as well. My first version of this step was a `check: |` multi-line scalar carrying `command=…` inside — that
is not a verb (the inline shorthand only parses on a single-line scalar), and the bed reported `check has no
verb`. Fixed in `ebdc4a3` ("fix(ubuntu): give the guest-is-resolute assertion a real verb") to the explicit field form the rest of the plan uses.
